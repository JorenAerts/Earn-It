# Gloop — alarm + wake-up missions (iOS + Android)

The app is **Gloop** (App Store: "Gloop: Your Wake-Up Buddy"; formerly "Earn It"). Bundle / applicationId `be.gloop.app`, App Group `group.be.gloop.app`, URL scheme `gloop://`, defaults keys `gloop.*`, products `be.gloop.app.pro.*`, Xcode project/target `Gloop`.

Alarm that keeps re-ringing until a mission is done. Later: Screen Time locks (FamilyControls).
Current milestone: **M1 (alarm + mission)**. iOS is in TestFlight; Android is being built (roadmap `docs/Android/PlayStore.md`).

## Repo layout
- `iOS/` — the iOS app (XcodeGen project, Swift packages, tests, fastlane, scripts). Everything below under "Layout" is iOS.
- `Android/` — the Android app (Gradle, Kotlin + Compose). See "Android" below.
- `Shared/Config/` — **content both apps ship**: `Pricing.json`, `Auth.json`, `Developer.json`, `Telemetry.json`, `SocialProof.json`, `Legal.json` + `Legal/`, `CoachLines.json`, `Quiz.json`, `TongueTwisters.json`, `MorningTips.json`, `Help.json`, `WhatsNew.json`, `Translations/`. Edit once, both apps get it (iOS bundles them via `project.yml`, Android as assets). Platform-only build config stays in `iOS/Config` (xcconfigs, `Gloop.storekit`) and `Android/` (`secrets.properties`).
- `Backend/` — Supabase (migrations, functions), shared by both apps. `docs/` — guides (App Store, Play Store, telemetry, localization, legal exports).
- Branch/commit scope by platform when it helps: `feat(android): …`, `feat(ios): …`.

## Rules
- iOS 26.1 minimum, Swift 6 strict concurrency. Keep logic pure + testable; UI/framework glue thin.
- New mission = new folder in `Missions/`, conform to `Mission`, add a case to `MissionKind` + `MissionRegistry`, add logic tests.
- Wake loop rule: the alarm has **one control, the system X/Stop** (no secondary button — iOS can't hide X). `StopAlarmIntent` (`supportedModes = .foreground(.immediate)`) → `alarmEnded` → system alarm silenced, countdown follow-up at +reArmMinutes, app opens on mission. `AlarmCoordinator` drives `AlarmSoundPlayer` (AlarmEngine): sound plays whenever `needsMission` is true (set in `persist`/`reload`), from the X press until all missions succeed or fail-safe. `UIBackgroundModes: audio` keeps it going when the app is left or the phone locked; resumes after interruptions. Follow-up countdown remains a backup if the app is force-quit. Only `missionSucceeded()` cancels follow-ups. App also jumps to the mission when launched/active while any alarm is alerting or a follow-up countdown runs (`reload`, `observeSystemAlarms`), or via `gloop://mission` (Live Activity tap). Fail-safe after `maxReArms`.

## AlarmKit / platform gotchas (append every on-device finding)
- AlarmKit + Screen Time only really work on a physical iPhone; Simulator = unit tests + UI only.
- `AlarmPresentation.Alert(title:secondaryButton:secondaryButtonBehavior:)` (no stop button arg) is iOS 26.1+; system always shows a Stop slider.
- Don't store `AlarmManager.shared` in a `@MainActor` property — Swift 6 flags "sending risks data race". Call `AlarmManager.shared` inline.
- Alarm button intents must be `LiveActivityIntent`s defined in the app target; `supportedModes = .foreground(.immediate)` opens the app.
- Cold launch from an intent: `onChange(of: scenePhase)` doesn't fire for the initial value — `RootView.task` calls `reload()` on first appear.
- Changing the alarm layout/sound needs re-scheduling existing alarms: `refreshAlarms()` runs on launch.
- Alarm button intents must silence the alarm themselves (`AlarmManager.shared.stop(id:)`, done in `AlarmCoordinator.alarmEnded`). A `.custom` secondary button does NOT stop the alert. On mission success / fail-safe, sweep *all* alarms from `AlarmManager.shared.alarms` (not just tracked IDs): stop the main plan alarm (keeps weekly repeat), stop + cancel everything else.
- `AlarmPresentation.Alert` only has a `title` — no subtitle. Title = `AlarmPlan.alarmTitle` ("Earn It - Math Problem"). Re-ring info lives in the countdown: follow-ups are `AlarmConfiguration.timer(duration:)` with `AlarmPresentation.Countdown`, rendered by our Live Activity widget (required for countdown UI). Metadata type must stay in `AlarmEngine` so app + widget share it.
- No `UIRequiresFullScreen` (deprecated iOS 26, TN3192). App supports all orientations + has `UILaunchScreen`; layouts must adapt (no fixed frames).
- Alarm sounds: `AlarmPlan.sound` is a `SoundChoice` (`.builtIn(AlarmSound)` / `.custom(id, name)` / `.appleMusic(AppleMusicPick)`; old JSON `"sound":"chime"` still decodes). Built-ins: `App/Sounds/Gloop_<raw>.caf`, generated by `iOS/scripts/generate_sounds.py` (30 s, 22 kHz mono LEI16; melodies are public-domain compositions in our own synthesis). AlarmKit rings `.named(sound.systemSoundFileName)`; `AlarmSoundPlayer` loops the matching file during the mission. Adding a built-in = enum case + generator function + file (test checks every case has a file).
- Own sounds (Pro): `Features/Sounds/` — `MySounds` (metadata `Library/Sounds/custom-sounds.json`, files `Library/Sounds/custom-<id>.caf`, max 20), `AudioClipExporter` (any decodable file → ≤30 s, mono 22.05 kHz 16-bit CAF, fades, normalised; DRM files fail with a clear error), `TrimSoundView` (waveform + 30 s window + preview), `RecordSoundView`. Deleting a sound in use resets those alarms to Classic Beep (RootView). `SoundChoice.customSoundsRingNatively`: whether AlarmKit plays files from `Library/Sounds` — verify with Settings › Developer › "Test: own sound via alarm" (plays Rising Siren if it works).
- Apple Music (Pro, MusicKit): pick song + start offset + fallback tone; the system alarm rings the fallback (DRM songs can't be alarm files); in-app `ApplicationMusicPlayer` takes over from the fallback loop when authorised + subscribed. Needs the MusicKit App Service on the App ID (paid program); otherwise search shows an error and the fallback tone plays. iOS gives apps no access to the built-in alarm tones, so a custom file is the only way to match.
- Logs: subsystem `be.gloop.app`, category `alarm` — filter in Console.app with the iPhone selected.
- **SwiftUI environment vs. presentations**: a `.sheet`/`.fullScreenCover` only inherits environment applied *outside* (after) it in the modifier chain. In RootView, keep presentations above `.environment(buddies)` / `LanguageEnvironment` / `\.paywall`, or pass the environment into the presented view. Bug found on-device: SuccessView's `@Environment(BuddiesModel.self)` was missing → SwiftUI trap → app closed after every completed mission.
- `Mission` protocol is not `@MainActor` (Identifiable conformance would cross isolation); only `makeView` is.
- Free personal team: provisioning expires after 7 days — re-run from Xcode. No App Groups / Family Controls until paid team.
